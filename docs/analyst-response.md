# Ответы аналитику ИЛЬ ДЕ БОТЭ

Коротко по вопросам 2 и 3 и то, что из репозитория не выводится. Развёрнуто: [`ARCHITECTURE.md`](ARCHITECTURE.md), [`INTEGRATION.md`](INTEGRATION.md), [`API.md`](API.md).

## 2. Сервис у нас или внешний?

По коду опросник — свой сервис: API, воркер, PostgreSQL, статика web-компонента, конструктор. ENSI внешняя: в неё воркер только отправляет профиль.

Репозиторий рассчитан на размещение у того, кто его получит. Пример встройки указывает на домен iledebeaute.ru. Отдельного внешнего SaaS (чужой хост, кабинет поставщика) в коде нет, но атрибут `api-base` и CORS позволяют оставить API на другом origin.

Кто держит production — ИЛЬ ДЕ БОТЭ или команда поставщика — в коде не записано. Это открытый вопрос владельцу.

## 3. Когда будут web-компонент и репозиторий бэкенда?

Они уже в этом репозитории, вторым репозиторием не вынесены.

- Бэкенд: `apps/api`, `apps/worker`, пакеты `packages/*`.
- Web-компонент: сборка `apps/web` → `dist/embed/idb-beauty-quiz.js` и `idb-beauty-quiz.iife.js`.

Публикации в npm нет. Даты передачи репозитория или собранного файла в репозитории нет.

## Открытые вопросы владельцу

1. Кто эксплуатирует production опросника: инфраструктура ИЛЬ ДЕ БОТЭ (вариант A в [`ARCHITECTURE.md`](ARCHITECTURE.md)) или поставщик, а ЛК только встраивает скрипт (вариант B)?
2. Какая дата передачи репозитория и собранного `idb-beauty-quiz.js`?
3. Какой прод-origin у статики и у API? `quiz.iledebeaute.ru` в runbook — пример.
4. Параметры JWT ЛК: JWKS или PEM, `iss`, `aud`, клейм id клиента. Совпадает ли этот id с id клиента в ENSI?
5. Контракт метода, которым ENSI принимает профиль (URL, метод, авторизация, идемпотентность). Без него `ENSI_SINK` остаётся `file`. Список — в [`ENSI.md`](ENSI.md).
6. Нужен ли ЛК сценарий «рисуем вопросы сами»? Для встройки web-компонента он не нужен. Если нужен, фронт ЛК начинает сам вызывать методы сессии.
7. Нужно ли при первом входе подтягивать профиль из ENSI? Метод чтения в адаптере есть, API и воркер его не вызывают.
